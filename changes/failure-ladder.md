Added
A failure ladder for a model stuck on one error, behind `limits.failure_ladder` (off by default): when the same error comes back within a turn through calls that differ, the third time its result tells the model to stop varying the call, the fifth asks for a different plan, and the eighth ends the turn as failed with the error and the attempts, which a subagent reports to its asker and which pauses a goal. Two errors are the same when the tool, the program a command runs and the last error lines match once numbers, paths, durations and quoted text are made alike. The thresholds are `limits.failure_note_at`, `failure_replan_at` and `failure_stop_at` (3, 5, 8). A new `RepeatNotice` event says when the core stepped in, for the existing note on an identical call too, and the eval runner counts it as `repeat_notices`; the protocol is at version 13.
