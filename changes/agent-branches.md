Added
Agents can branch off a git project and merge back: the new `branch` tool makes a branch `agent/<name>` from the current one in a worktree beside the repository, and the thread's files, commands and sandbox move there (a restart finds it again), while memory, project variables and episodes stay with the saved project. `status`, `commit`, `merge`, `abort`, `abandon` and `list` go through the core's git layer, never a shell: a merge first brings the base branch into the worktree so conflicts are resolved there, then merges back with a merge commit and removes the worktree and the merged branch. A merge into the user's branch, and abandoning a branch that has work on it, ask the user every time in every mode; abandoning commits uncommitted work to the branch and keeps any branch with unmerged work. `ask_agent` takes `isolated: true` to give a subagent a branch of its own that the asking agent merges. In sandbox mode a command in a worktree may write only the git objects, the agents' branch refs and that worktree's own git data, never the repository's config or hooks. Desktop's Git panel, the browser's chat header and the terminal's status line show the branch a chat works on.
